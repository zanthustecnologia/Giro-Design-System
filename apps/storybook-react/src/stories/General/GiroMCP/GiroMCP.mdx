# Giro MCP

O **Giro MCP** é um servidor <a href="https://modelcontextprotocol.io" target="_blank" rel="noopener noreferrer">Model Context Protocol</a> que expõe o Giro Design System para ferramentas de IA. Com ele ativo, assistentes como GitHub Copilot e Cursor consultam componentes, props, tokens e guias de migração diretamente da fonte, sem depender do conhecimento pré-treinado do modelo.

Sem o MCP, a IA desconhece os componentes do Giro DS e tende a gerar código com props incorretas ou variantes inexistentes. Com ele, o código gerado reflete a API real do design system.

## Tools disponíveis

- **`list-giro-components`**: Lista todos os componentes públicos do `@giro-ds/react`
- **`get-giro-component-metadata`**: Props, tipos, valores padrão e descrições de um componente
- **`get-giro-component-examples`**: Exemplos de uso prontos para um componente específico
- **`list-giro-tokens`**: Tokens do `@giro-ds/tokens`, filtráveis por categoria ou nome
- **`find-giro-component`**: Busca semântica por componente em português ou inglês
- **`resolve-giro-token`**: Retorna os tokens mais adequados para uma intenção de design
- **`review-giro-usage`**: Analisa JSX/TSX em busca de props inválidas e obrigatórias ausentes
- **`review-giro-css`**: Detecta valores hardcoded em CSS e sugere o token equivalente
- **`generate-giro-component`**: Gera um snippet JSX/TSX a partir de uma descrição em linguagem natural
- **`get-giro-system-prompt`**: Gera um system prompt do Giro DS para uso em ChatGPT, Claude ou Cursor Rules
- **`giro-migration-guide`**: Guia de breaking changes entre versões (v2 > v3 > v4)
- **`get-giro-changelog`**: APIs depreciadas com versão, prop afetada e substituição sugerida

## Instalação

### VS Code com GitHub Copilot

Instale o pacote como dependência do seu projeto. O arquivo `.vscode/mcp.json` é criado automaticamente via `postinstall`:

```bash
npm install @giro-ds/mcp
```

Recarregue o VS Code e ative o servidor no painel MCP do Copilot Chat.

Se preferir usar sem instalar no projeto, crie o `.vscode/mcp.json` manualmente:

```json
{
  "servers": {
    "giro-ds": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@giro-ds/mcp"]
    }
  }
}
```

### Cursor

Edite `~/.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "giro-ds": {
      "command": "npx",
      "args": ["-y", "@giro-ds/mcp"]
    }
  }
}
```

## Como usar

Com o servidor ativo, use o modo **Agent** do Copilot Chat e faça perguntas diretamente:

- *"Quais são as props do Drawer?"*
- *"Crie um formulário de login com TextField, Select e Button"*
- *"Qual componente usar para exibir uma notificação de sucesso?"*
- *"Qual token usar para a cor primária?"*
- *"O que mudou do v3 para o v4?"*
- *"Revise esse código: estou usando o Button corretamente?"*
- *"Esse CSS usa valores hardcoded?"*
- *"Quais props foram depreciadas no Dialog?"*

## Para desenvolvedores do Giro DS

Se você contribui com o monorepo, o servidor já está configurado. O `.vscode/mcp.json` na raiz aponta para o build local em `packages/mcp/dist/index.js`.

### Rodando localmente

```bash
# Compilar o pacote MCP
pnpm --filter @giro-ds/mcp build

# Iniciar o MCP Inspector (interface de teste)
pnpm --filter @giro-ds/mcp inspect
```

### Estrutura do pacote

O `packages/mcp` segue uma arquitetura modular. A lógica de cada tool está isolada em `src/tools/`, os dados React em `src/data/react/`, e as funções compartilhadas de scoring e formatação em `src/lib/`. O `src/index.ts` apenas registra as tools no servidor MCP, sem lógica de negócio.

Para entender a arquitetura completa e o plano de evolução do pacote, consulte [`packages/mcp/ARCHITECTURE.md`](https://github.com/zanthus-tecnologia/design-system-monorepo/blob/main/packages/mcp/ARCHITECTURE.md).

### Regenerando metadados de componentes

Os metadados são gerados a partir dos arquivos `.types.ts` do `@giro-ds/react`, usando `ts-morph` para ler o AST TypeScript e extrair props, descrições JSDoc, exemplos via `@example` e valores padrão via `@default`.

```bash
# Regera src/data/components.generated.ts
pnpm --filter @giro-ds/mcp generate

# Recompila
pnpm --filter @giro-ds/mcp build
```

Execute `generate` sempre que um componente for adicionado ou tiver sua interface alterada.

### Adicionando metadados manualmente

Quando a geração automática não é suficiente (descrições de alto nível, exemplos complexos ou componentes com tipos union), edite `packages/mcp/src/data/components.ts`:

```ts
{
  name: 'NomeDoComponente',
  description: 'Descrição objetiva do que o componente faz.',
  category: 'Components',
  keywords: ['formulário', 'seleção'],
  props: [
    {
      name: 'variant',
      type: "'filled' | 'outlined'",
      required: false,
      defaultValue: "'filled'",
      description: 'Variante visual'
    },
  ],
  examples: [
    '<NomeDoComponente variant="filled">Conteúdo</NomeDoComponente>',
  ],
}
```

Entradas manuais são mescladas com as geradas. Se um componente já existe no arquivo gerado, a versão gerada tem precedência e a entrada manual é ignorada.

### Regenerando tokens

Os tokens são gerados a partir do CSS compilado pelo `@giro-ds/tokens`.

```bash
# Regera src/data/tokens.generated.ts
pnpm --filter @giro-ds/mcp generate:tokens

# Recompila
pnpm --filter @giro-ds/mcp build
```

Execute após qualquer alteração no `@giro-ds/tokens`:

```bash
pnpm --filter @giro-ds/tokens build
pnpm --filter @giro-ds/mcp generate:tokens
pnpm --filter @giro-ds/mcp build
```

### Adicionando um token manualmente

Para incluir ou sobrescrever um token sem regenerar, edite `packages/mcp/src/data/tokens.ts` e adicione no array `MANUAL_OVERRIDES`:

```ts
{ name: '--meu-token', value: '#ff0000', category: 'color-brand' }
```

Tokens em `MANUAL_OVERRIDES` com o mesmo nome que os gerados substituem o valor gerado. Novos tokens são adicionados ao final da lista.
